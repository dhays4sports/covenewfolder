# RC-SMS-1.9.5 — Global Consent + Suppression Boundary

Status: **COMPLETE**  
Release: **CoverageFit 3.20.70**  
Previous baseline: **CoverageFit 3.20.69 / RC-SMS-1.9.4**

## Objective

Make SMS permission authoritative at the 408-FARMERS sender/recipient relationship so no CoverageFit or adjacent programmatic workflow can bypass a customer STOP, a persisted application suppression, or a known provider-side block.

## Delivered

- Added `server/sms-consent-core.mjs` as the single channel-level consent model.
- Added backward-compatible `smsConsent` projection inside the existing `sms_conversations` record; no D1 migration or new table.
- Consent tracks `status`, `optedOutAt`, `optedInAt`, `source`, `lastCommand`, `providerStatus`, `providerUpdatedAt`, and `updatedAt`.
- Added a centralized permission snapshot consumed by the SMS gateway.
- Programmatic sends are permission-checked when prepared **and immediately before RingCentral delivery**.
- Retry/scheduled work re-enters the same gateway and therefore re-checks current consent at execution time.
- Retry work denied because of STOP/provider suppression is marked `suppressed`, not repeatedly retried as a transient delivery failure.
- STOP suppresses the entire channel while preserving the underlying CoverageFit workflow step and workflow episode.
- START restores channel permission only. It does not restart or resume the old CoverageFit flow; preserved workflows remain producer-owned/human-only until explicitly resumed.
- `RESTART` remains the explicit workflow restart command after permission has been restored.
- Manual/unregistered RingCentral outbound remains human-classified and cannot silently clear `smsConsent`.
- `producer_console` outbound provenance is explicitly `human_initiated`; other programmatic origins remain `automated`. Both still honor global channel suppression when sent through CoverageFit.
- Added protected `/api/sms/consent/` read/reconciliation boundary for provider consent signals.
- Provider `opted_out` or `blocked` forces local suppression. A later provider `active` status cannot by itself override an existing application/customer opt-out.
- Producer continuity actions cannot resume CoverageFit automation while the channel remains suppressed.
- SMS Operations exposes redacted consent status, provider status, timestamps/command provenance, and suppressed retry counts.
- Live conversation schema advanced to `1.6`; orchestration schema advanced to `1.2`; outbound registry schema advanced to `1.2`.

## Consent contract

```text
smsConsent
  schemaVersion
  build
  status: active | opted_out
  optedOutAt
  optedInAt
  source: legacy | customer_command | provider | producer | system
  lastCommand
  providerStatus: unknown | active | opted_out | blocked
  providerUpdatedAt
  updatedAt
```

## Permission precedence

```text
known provider blocked/opted_out
        ↓
application/customer opted_out
        ↓
channel orchestration suppression
        ↓
workflow/ownership permission
        ↓
provider delivery
```

Consent is checked independently from workflow ownership. A customer may restore channel permission while an old workflow remains paused.

## Live keyword behavior

### STOP

- `smsConsent.status = opted_out`
- channel becomes `opted_out`
- automation mode becomes `suppressed`
- active workflow state is preserved and paused
- reply context is cleared
- no live automated acknowledgement is generated by CoverageFit

### START

- `smsConsent.status = active`
- `optedInAt` and `lastCommand` are updated
- channel becomes active
- preserved old workflow is **not** resumed
- if a workflow exists, relationship becomes producer-owned/human-only until explicit resume
- if no workflow exists, relationship returns to neutral/assist-only

## Programmatic boundary

Every application sender continues through `sendSmsThroughGateway()`. The gateway now evaluates the consent boundary twice: before registration/send preparation and immediately before `sendRingCentralSms()`.

The compatibility `/api/sms/outbound/register` path also rejects pre-registration against a suppressed relationship.

## Provider reconciliation

Protected route:

```text
GET  /api/sms/consent/?conversation_id=<opaque-id>
POST /api/sms/consent/
```

Provider reconciliation POST accepts only:

```json
{
  "conversationId": "opaque live SMS id",
  "action": "reconcile_provider",
  "providerStatus": "unknown | active | opted_out | blocked"
}
```

This route is intentionally producer-authorized and same-origin. It is a bounded hook for provider/carrier evidence used by later certification; it is not a customer-facing opt-in override.

## Frozen boundaries

- No new SMS database/table.
- No change to Protection Score or CoverageFit assessment semantics.
- No automatic specialized service/life/commercial bot responses.
- No producer action may override STOP to restart automation.
- No carrier-certification claim until RC-SMS-1.10.
- No direct application `sendRingCentralSms()` call outside the gateway.
